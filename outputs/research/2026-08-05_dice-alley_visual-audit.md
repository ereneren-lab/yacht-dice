## 개요

어제(2026-08-04) 전략 문서는 코드 기반으로 **정보 구조**와 **정확성**(배지 오류, 5종 vs 13종)을 다뤘다. 이번 문서는 **실제 렌더링된 화면**을 보고 **시각 위계**, **일관성**, **정보 밀도**, **톤**을 다룬다. 

어제 이미 확정된 사항(온라인 배지 누락, 마스코트 미사용, 레벨/도전과제 5종 한계)은 반복하지 않으며, **화면에서만 판단 가능한 미감·위계·일관성 문제**를 우선한다.

## 1. 첫 화면(viewport top) 3초 시선 흐름과 위계

### 1-1. 시선 순서는 적절하나, 정보 위계는 카드에서 깨진다 [화면]

**phone-01-hub.png 기준**, 3초 내 시선 흐름:
1. **로고 + 제목** (황금색 배경) → ✅ 적절
2. **리드 문구** ("뒷골목 놀이터 — 설치 없이 링크 하나로 친구와 13가지") → ✅ 적절 (문구는 어제 지적)
3. **"▶ 바로 한 판" 섹션** (4개 카드) → ⚠️ 문제 있음

### 1-2. "바로 한 판" 4개 카드의 비주얼 무게가 불균형 [화면]

**phone-01-hub.png에서:**

| 위치 | 게임명 | 아이콘 | 카드 높이 | 시각적 강도 | 문제 |
|---|---|---|---|---|---|
| 1 | 너클본즈 | 🦴 | 크고 높음(full width) | **강함** | 아이콘 2배 크고 제목도 굵고 부제 길다 |
| 2 | 하이로우 | 🔺 | 작고 낮음(1/2 width) | 약함 | 아이콘 작고 제목도 일반 |
| 3 | 요트다이스 | 🎲 | 작고 낮음(1/2 width) | 약함 | 하이로우와 동일 |

**판단**: 카드 레이아웃이 2×2이지만 CSS 그리드로 1-wide 2-wide 혼합 설정됨. [추정] `grid-column: span 2`와 `span 1` 혼합인 듯.

## 3. 카드 부제(subtitle)의 정보 종류가 불일치 [화면]

**"바로 한 판" 4개 카드의 부제 (`phone-01-hub.png`):**

| 게임 | 부제 | 정보 종류 |
|---|---|---|

| 항목 | 폰 | 데스크톱 |

| 허브 정보 | 위에 표시 | 위에 표시 (중앙) |

**추정**: 모바일은 2.5초면 첫 게임을 선택할 수 있지만, 데스크톱은 스크롤 필요.

## 8. 이미 알려진 문제들의 시각적 증거 [화면]

### 8-1. 윷놀이 시간 배지(7~10분) 과대 [화면]

**phone-01-hub.png:**
- "윷놀이 · 🕐 7~10분 · 말 4개 완주"

**근거** [코드]:
- 기본 설정: `cfg={n:2, markers:4}` (2인, 말4개)
- 실측 중앙값: 2분 33초
- 배지: 7분 05초 (3배 이상)
- 원인: `balance-sim.js`가 윷만 `n:4`(4인)로 시뮬레이션함

**시각적 영향**: 사용자가 "7~10분 걸린다"고 읽고 시작하면, 2분 33초 만에 끝나는 것에 놀람 → 신뢰도 하락.

**충돌**: 같은 사용자 데이터인데 판수가 1 vs 3.

**원인** [코드]: 허브 `GAMES` 배열(5종)만 집계 vs 전체 게임 박스는 13종 집계 (어제 문서에서 확인됨).

**시각적 증거**: [화면] 이 불일치를 **사용자가 그대로 본다** → 서비스 신뢰도 하락.

## 10. 정보 밀도와 시각적 호흡 [화면]

### 10-1. 스크롤 구간별 정보 밀도 비교 [화면]

| 구간 | 콘텐츠 | 밀도 |
|---|---|---|
| 허브 상단 (로고~바로한판) | 로고·제목·4개 카드 | 보통 |
| 카테고리 pills | 6개 pill | 높음 |
| 코인/프로필/레벨 | 3개 카드 | 보통 |
| 요약(4통계) | 4개 숫자 + 라벨 | **높음** |
| 도전과제(8개) | 8개 아이콘 + 라벨 | **높음** |
| 오늘의 목표(3개) | 3개 아이콘 + 라벨 | 보통 |
| 테마 + 광고/프리미엄 | 3개 선택지 + 버튼 | 보통 |

**패턴**: 도전과제·요약 영역이 **의도적으로 정보 밀도가 높음** → 숙련 사용자는 한눈에 게이지, 신규 사용자는 혼란.

**제안**: "요약" 영역을 드롭다운하고 기본으로는 "**당신은 아직 플레이하지 않았습니다**"라는 메시지로 단순화.

### 11-1. 폰(384×748) vs 실기기(1080×2340) 레이아웃 차이 [화면]

**헤드리스 폰(384×748):**

- 카드 너비: ~900px (여백 90px × 2)
- 텍스트: 더 커 보임

**판단**: [화면] 두 캡처가 다른 CSS 미디어 쿼리로 렌더링되는 것 같음. 헤드리스 폰이 모바일 타겟인지 명확하지 않음.

## 13. 전략가에게 넘길 결정 사항

### 이 문서만으로 실행 가능한 것(UX 담당자가 그냥 고칠 수 있음)

1. **"바로 한 판" 카드 크기 통일** → 4개 모두 같은 높이로
2. **황금색 사용 범위 축소** → 로고·제목·CTA 버튼 3가지만 사용, 다른 강조는 회색/흰색으로
3. **라이트 테마 황금색 명도 조정** → RGB 증가 또는 대체 색상 사용
4. **메타 정보 재배열** → 레벨/도전과제를 코인 위로 이동
5. **게임 셋업 배경색 통일** → 모든 게임이 선택한 테마(에스프레소/흑임자/라이트)를 따르게 설정

### 기획·개발과 함께 검토 필요한 것

6. **"바로 한 판" 4개 게임 선정 기준** → 현재 1·4번 게임이 과강조되는 이유가 의도된 건지?
7. **코인의 첫 방문자 설명** → 온보딩에서 코인이 뭐고 어떻게 얻는지 설명하는 단계가 있나?
8. **게임 셋업 깊이 표준화** → 윷(복잡)과 요트(단순)의 차이를 사용자에게 미리 알려야 하나?
9. **데스크톱 정보 밀도** → 게임 리스트를 펼쳐 보여주는 것이 실제 사용자 이탈을 줄이나? (측정 필요)
