# 주사위 골목 앱 UX 실측 감사

- 작성일: 2026-07-29
- 대상: `com.jaesung.yachtdice` (Galaxy A16 / SM-A165N, 1080×2340 @450dpi)
- 앱 웹뷰 실측 뷰포트: **384×748 CSS px**
- 방법: adb + CDP로 실기기 웹뷰에 직접 붙어 계측 (`scripts/phone/`)
- 기기 상태: 설치본 2026-07-28 빌드 · 저장소 v1.245.0

> ⚠️ 이 문서는 **관찰된 사실**이다. 원인 해석과 개선안은 전략 단계에서 분리해 다룬다.
> 실제 사용자 데이터(Plausible)는 아직 표본이 없어 **행동 근거가 아니라 화면 근거**만 담았다.

---

## 1. 리서치 목적

"게임이 별로인가, 아무도 온 적이 없나"를 구분하려 계측을 넣었지만(v1.241~), 아직 표본이 없다.
그 사이 확인 가능한 것은 **"온 사람이 실제로 한 판까지 갈 수 있는 구조인가"** 다.
이 감사는 신규 유저가 앱을 처음 켠 순간부터 첫 판까지의 경로를 실기기에서 잰다.

## 2. 조사 범위와 방법

| 대상 | 계측 내용 | 스크립트 |
|---|---|---|
| 허브 첫 화면 | 첫 카드 위치, 스크롤 깊이, 탭 타깃, 글자 크기 | `scripts/phone/audit-hub.js` |
| 신규 유저 진입 | 첫 방문 오버레이, 시작 버튼 도달성 | `scripts/phone/audit-funnel.js` |
| 셋업 화면 | 블록별 높이 예산, 요소 겹침 | 인라인 CDP |
| 인게임 | 넘침, 화면 밖 버튼 | 인라인 CDP |

신규 유저 재현은 `localStorage.clear()`로 했다 — 기존 기기에는 튜토리얼 시청 기록(`alley_tut_*`)과
전적이 남아 있어 **첫 방문 경험이 가려진다.** 이 감사의 핵심 조건이다.

## 3. 핵심 발견

### 3-1. 허브 — 첫 화면의 43%가 게임이 아니다

| 항목 | 실측값 |
|---|---|
| 문서 높이 | 3567px = **4.8화면** |
| 첫 게임 카드 시작 위치 | y=323px (**첫 화면의 43% 지점**) |
| 첫 화면에 온전히 보이는 카드 | **2개** / 13개 |
| 마지막 게임(도둑잡기) 도달 | **3.1번째 화면** |

첫 화면 상단 323px의 구성: 로고·타이틀·소개문 → **방 코드 입력창** → 카테고리 칩 2줄.

'방 코드로 참가'는 **초대받은 사람만** 쓰는 기능인데 첫 화면 최상단 고정석을 차지한다.
신규 유저에게는 입력할 코드가 없다.

게임별 스크롤 깊이 (몇 번째 화면에서 나타나나):

```
 1. 너클본즈   0.4      6. 알까기     1.5     11. 원카드    2.7
 2. 요트       0.6      7. 섯다       1.8     12. 하이로우  2.9
 3. 라이어     0.8      8. 블랙잭     2.1     13. 도둑잡기  3.1
 4. LCR        1.1      9. 바카라     2.3
 5. 윷놀이     1.3     10. 인디언     2.5
```

### 3-2. 모든 게임이 전체화면 가림막 2겹으로 시작한다

첫 방문(저장소 비운 상태) 6개 게임 전수:

| 게임 | 가림막 | 시작 버튼 상태 |
|---|---|---|
| 너클본즈 | `setupOv`(100%) + `helpOv`(100%) | 가려짐 → 1탭 후 누를 수 있음 |
| 요트 다이스 | `bg`(100%) + `tutOverlay`(100%) | 가려짐 (`tut-box`) |
| 윷놀이 | `setupOv`(100%) + `tutOverlay`(100%) | 가려짐 (`tutOverlay`) |
| 라이어 | `setupOv`(100%) + `helpOv`(100%) | 가려짐 → 1탭 후 누를 수 있음 |
| 원카드 | `setupOv`(100%) + `tutOverlay`(100%) | 가려짐 (`tutOSkip`) |
| 섯다 | `tutorialOv`(100%) | 가려짐 → 1탭 후 누를 수 있음 |

**6/6 게임에서 첫 진입 시 '시작' 버튼이 다른 요소에 덮여 있다.**
튜토리얼·규칙이 자동으로 뜨는 것은 의도된 설계지만, 결과적으로 신규 유저는
**게임 화면을 보기 전에 읽을거리부터 만난다.**

### 3-3. 셋업 화면 — 신규 유저에게 21%가 빈 껍데기

너클본즈 셋업 블록별 높이 예산 (뷰포트 748px / 내용 892px):

| 블록 | 높이 | 신규 유저에게 보이는 것 |
|---|---|---|
| 제목 + 설명 | 90px | 게임 소개 |
| `#levelBar` | 72px | **LV 1 · 0/60 XP** (게이지 0%) |
| `#statsbar` | 18px | **"아직 전적이 없어"** |
| `#achbar` | 98px | **🔒 잠긴 배지 6개** |
| 규칙 / 튜토리얼 버튼 | 80px | |
| 테마 선택 | 29px | |
| 상대 · 난이도 · 아이템 · 매치 | 264px | **실제 선택지** |
| `#startBtn` | 53px | |

**레벨·전적·업적 = 188px (21%)가 신규 유저에게는 전부 0·잠김 상태다.**
성취 시스템은 리텐션 장치인데, 아직 아무것도 없는 사람에게 먼저 보여준다.

### 3-4. 🟠 `시작` 버튼이 도착 시점에 옵션을 덮는다

```
시작버튼 position=sticky
겹친 요소(위→아래): #startBtn > #optItems > #itemWrap > div.sheet

스크롤 컨테이너 #setupOv · 스크롤 여유 185px
  scroll=0   #itemWrap top=666 bot=734  화면안=O  히트=#startBtn   닿나=X
  scroll=끝  #itemWrap top=481 bot=549  화면안=O  히트=#optItems   닿나=O
```

`fit-setup.js`(함정 #21 처방)가 붙인 sticky 시작 버튼이 **화면에 도착한 시점(scroll=0)에
`#itemWrap`(아이템전 설정)을 덮는다.** 스크린샷에서도 시작 버튼 뒤로 두 버튼이 잘린 채 비친다.

**단, 끝까지 스크롤하면(185px) 닿는다 — '접근 불가'는 아니다.**
문제는 **처음 보는 화면에서 가려져 있고, 아래에 뭔가 더 있다는 단서가 없다**는 것이다.
sticky-bottom 바가 스크롤 콘텐츠 위에 뜨는 구조 자체의 부작용이다.

→ 넘침을 없앤 처방이 새 가림을 만들었다. 함정 #21의 재발이 아니라 그 **부작용**이다.
→ 근본 원인은 **셋업 시트가 뷰포트보다 길다는 것**(892px > 748px)이다. 버튼을 고정하는 대신
   시트를 줄이면 고정 자체가 필요 없어진다 (§3-3의 188px가 바로 그 후보다).

### 3-5. 탭 타깃과 글자 크기

| 항목 | 개수 | 비고 |
|---|---|---|
| 44px 미만 탭 타깃 (허브) | **35개** | 아바타 칩 36×36 ×16, 카테고리 칩 31px 높이 ×5, 방코드 입력 39px |
| 13px 미만 텍스트 (허브) | **135개** | 최소 10.5px (카테고리 개수 배지) |

44px는 WCAG 2.5.5 / Apple HIG 기준이다. 카테고리 칩(높이 31px)과 아바타 칩(36×36)은
**손가락으로 정확히 누르기 어려운 크기**다.

### 3-6. 인게임은 견고하다 (수정 성과 확인)

너클본즈·요트·윷놀이 3종 인게임 실측:

```
세로 넘침 0px · 가로 넘침 0px · 화면 밖 버튼 0개
```

## 4. 기회 영역

1. **첫 화면 재배치** — 방 코드 입력을 접고 게임 카드를 위로 올리면 첫 화면 카드 수 2 → 4~5개.
2. **첫 방문 가림막 정리** — 자동 오버레이를 줄이거나 순서를 바꿔 '시작'을 먼저 보이게.
3. **신규/기존 유저 화면 분기** — 전적 0이면 레벨·업적 블록을 접고 선택지를 먼저.
4. **`#itemWrap` 가림 해소** — sticky 버튼 아래 여백 확보 (함정 #21-b와 같은 계열).
5. **탭 타깃 44px 확보** — 칩·아바타 높이 조정.
6. **상단바 정리** — 아이콘 수 축소 또는 더보기로 묶기.

## 5. 전략 단계에서 판단할 질문

- 이 앱의 **첫 목표 행동**은 무엇인가? (한 판 플레이 / 친구 초대 / 재방문)
- 13종 전부를 동등하게 노출할 것인가, **대표 3~4종을 앞세울** 것인가?
- 튜토리얼 자동 노출을 **유지**할 것인가, 첫 판 이후로 미룰 것인가?
- 레벨·업적은 **신규 유저에게 동기**인가, 아직 비어 있는 소음인가?

## 6. 확인하지 못한 것

- **실사용 데이터 없음** — Plausible 표본이 아직 없어 이탈 지점을 행동으로 확인하지 못했다.
  이 문서의 모든 판단은 화면 구조 근거다.
- 온라인 멀티플레이 진입 경로(방 만들기/참가)는 이번에 측정하지 않았다.
- 13종 중 6종만 첫 방문 퍼널을 쟀다 (kb·yacht·yut·ld·onecard·seotda).
- 헤드리스 `npm run audit:ux`(13게임 × 9뷰포트)는 별도 진행 중 — 결과 미반영.
- 실사용자 인터뷰·경쟁 앱 비교는 하지 않았다.
