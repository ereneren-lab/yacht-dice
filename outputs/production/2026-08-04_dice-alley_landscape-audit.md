# 가로 모드 감사 — 주사위 골목 12종 + 허브

작성 2026-08-04 · 대상 `kb · yacht · ld · lcr · alkkagi · seotda · indianpoker · onecard · oldmaid · blackjack · baccarat · highlow` + `index.html`
(윷놀이는 다른 작업자 담당이라 제외)

---

## 1. 왜 감사가 통과하는데 사람은 불편했나

`npm run audit:ux`는 가로 뷰포트(640×360 · 844×390 · 1024×768)를 이미 돌고 있었고 **경고 0으로 통과**하고 있었다.
그런데 실사용자는 "가로가 상당히 불편하다"고 했다. 재보니 **감사가 보는 것과 사람이 겪는 것이 달랐다.**

| 감사가 보던 것 | 사람이 겪던 것 |
|---|---|
| 문서가 넘치나 (`scrollHeight − innerHeight`) | 판이 눌려 **카드가 잘려나갔다** — `overflow:hidden`이라 문서는 안 넘친다 |
| 버튼이 화면 안에 있나 | 상태 글이 **손패 위에 얹혔다** — 겹침은 넘침으로 안 잡힌다 |
| 버튼이 가려지지 않았나 | **좌우 200px씩을 버리고** 가운데만 좁게 썼다 — 넘침 0이라 통과 |
| — | 화면을 넓게 돌렸는데 **판이 오히려 작아졌다**(알까기 336→248px) |

가장 극단적인 실측: **바카라 판(`#table`)이 740×360에서 61px**이었다. 카드가 88px이니 애초에 들어갈 수 없다.
문서 넘침은 0이었다.

## 2. 찾은 문제 (전부 실기기 크기 뷰포트에서 조작해 확인)

측정 방법: `scripts/browser-test/cdp.js`로 헤드리스 크로미움을 띄워
게임 시작 → 실제 액션(칩 걸기·딜·카드 내기·베팅) → 그 상태의 rect를 잰다. 스크린샷으로 눈으로도 확인했다.

### A. 카드 6종 — 폭은 버리고 세로는 눌렸다 (심각)
`indianpoker · onecard · oldmaid · blackjack · baccarat · highlow`
이 6종은 `orientation:landscape` 규칙이 **하나도 없었다.** `.app{max-width:560px}` 하나로 세로·가로를 다 처리했다.

- 폭 사용률 **57~63%** (932px 화면에서 532px만 사용, 좌우 200px씩 버림)
- 판 높이가 61~326px로 눌림 → `.table{overflow:hidden}` 안에서 카드가 **잘림**
  - 블랙잭: 딜러 패 위쪽이 잘리고, 딜러 합계와 상태 글이 **내 카드 위에** 얹힘
  - 바카라: 뱅커 패 위·플레이어 패 아래가 동시에 잘리고 좌석 이름표가 사라짐
  - 하이로우: 카드 아래 40%가 잘리고 **상태 글이 통째로 사라짐**(판 밖으로 밀려남)
  - 원카드: 상태 글이 내 손패 위에 겹침
  - 인디언 포커: 내 카드가 팟·상대 카드·상태 글과 **4겹으로 겹침**

### B. 알까기 — 돌렸더니 판이 26% 작아졌다
세로 390×844에서 판 **336×336** → 가로 844×390에서 **248×248**.
원인: `resizeCanvas()`가 `availH = 화면높이 − 캔버스top − 안내높이 − 16`으로 판을 잡는데,
차례·점수(`.stagehead`)가 판 **위**, 안내(`.stagenote`)가 판 **아래**에 있어 세로를 88px 먹었다.
좌우는 각각 270px씩 비어 있었다.

### C. 요트 — 점수판 15줄 중 5줄만 보였다
`.sheetwrap{max-height:calc(100dvh − 168px)}`는 세로 폰 기준으로 정한 숫자다.
가로 844×390에서 점수판이 60~282px에 갇혀 **아래 108px이 그냥 비어 있었고**, 15줄 중 5줄만 보였다.
"점수를 어디에 넣을지 고르는 것"이 이 게임의 유일한 선택인데 그게 매번 내부 스크롤 뒤에 있었다.

### D. 섯다 — 판 아래 100px이 죽어 있고 베팅 버튼이 37px
- `.tablewrap{min-height:230px}`은 '넘치지 않게' 정한 값이라 390px 화면에서 **판 아래 100px이 공백**
- `max-width:760px`가 가로에서도 살아 932px 화면에서 192px 버림
- 베팅 버튼 6개가 250px 안에서 **37px 폭** (가로 탭 타깃 하한 40px 미달)
- 내 패(`#mine`, 판 바닥 기준 absolute 181px)와 팟(`.pot`, 판 높이 44%)이 **세로로 겹침**
- 상대 자리가 판 위로 26~32px 잘리고, 그 바람에 **AI 말풍선이 상단바(제목)를 덮음**

### E. 라이어 다이스 — 폭의 27~34%를 버림
`.wrap`에 두 규칙이 걸려 있었다. ①폭 <781px엔 세로용 `max-width:560px`, ②폭 ≥781px엔
"오프라인은 사이드가 비니 좁게"라는 `max-width:640px`. **둘 다 세로 화면 전제**인데 가로에도 걸렸다.

### F. 좌·중·우 — 좁은 가로에서 폭 낭비 + 18px 체크박스
폭 <781px 가로(740×360)에서 `max-width:560px`가 남아 폭 72%만 사용.
`#autoChk`(자동 굴리기) 18×18, 반응 버튼 35px.

### G. 너클본즈 — 미세 넘침
740×360에서 +4px, 932×430에서 +1px.

### H. 허브(`index.html`) — 가로에서 문서가 7.5화면
`min-width:781px`면 전체 게임 목록(`#allGames`)을 자동으로 펼치는데,
**가로로 돌린 폰(844×390)이 여기 걸린다.** 폭은 넓지만 높이는 390px뿐이라
13종을 펼치면 문서가 **7.49화면**(넘침 2532px)이 됐다. 세로 390×844에선 1.39화면이다.
폭도 520/844(62%)만 썼다.

## 3. 고친 것과 전·후 수치

### 3-1. 카드 6종 — 공용 `public/landscape.css` 신설
`.app`을 **[판 | 조작부] 2열 그리드**로 바꿨다. 상단바만 두 열을 걸친다.
→ 판이 화면 높이를 전부 갖고, 남는 가로 폭은 조작부가 쓴다.
→ 조작부가 오른쪽 세로 스택이 되어 **가로로 쥔 오른손 엄지**에 붙는다.
6개 HTML에는 `<link rel="stylesheet" href="landscape.css">` 한 줄씩만 넣었다(규칙은 한 곳).

**판 크기 (px)**

| 게임 | 844×390 전 → 후 | 740×360 전 → 후 |
|---|---|---|
| baccarat | 536×**91** → 599×340 | 536×**61** → 521×310 |
| highlow | 536×148 → 599×340 | 536×118 → 521×310 |
| blackjack | 536×161 → 599×340 | 536×131 → 521×310 |
| indianpoker | 536×243 → 599×340 | 536×213 → 521×310 |
| onecard | 536×258 → 599×340 | 536×228 → 521×310 |
| oldmaid | 536×326 → **810**×340 | 536×296 → **706**×310 |

**폭 사용률** — 6종 전부: 844×390 63→**97%** · 740×360 72→**96%** · 932×430 **57→97%**

**잘림/겹침** — 6종 전 뷰포트에서 **0건**(감사 ③④).

개별 처방 두 가지를 더 넣었다.
- 원카드/도둑잡기는 [상대 자리 | 더미 | 내 손패] 3층이라 판이 340px가 돼도 33px이 모자랐다
  → 층마다 한 단계씩 줄이고, ≤400px 높이에선 상대 뒷면 부채를 접었다(장수는 숫자로 이미 보인다).
- 인디언 포커는 팟·상태 글이 판 한가운데 absolute라 세로로는 자리가 안 났다(남는 띠 51px)
  → **팟은 왼쪽, 상태 글은 오른쪽**으로 빼서 겹침을 없애고 동시에 남는 폭을 썼다.

### 3-2. 알까기 — 판 옆으로 정보 이동
`.stagewrap`을 가로에서 그리드로 바꿔 차례·점수·안내를 판 **오른쪽**에 두고,
`resizeCanvas()`가 그 경우 안내 높이를 빼지 않게 했다(`display==='grid'`로 판정).

| | 전 | 후 |
|---|---|---|
| 844×390 | 248×248 | **311×311** (+25%) |
| 740×360 | 220×220 | **281×281** (+28%) |
| 932×430 | 288×288 | **351×351** (+22%) |
| 390×844 (세로) | 336×336 | 336×336 (변화 없음) |

⚠️ `align-items:start`가 필수다 — `center`로 두면 캔버스가 작아질수록 top이 내려가
`availH`가 또 줄어드는 되먹임(측정→축소→측정)이 생긴다.

### 3-3. 요트 — 점수판이 남는 세로를 가져가게
`.sheetwrap{max-height:calc(100dvh − 168px)}` → `calc(100dvh − 76px)` (가로 블록 안에서만).

| | 점수판 높이 전→후 | 보이는 줄 전→후 |
|---|---|---|
| 844×390 | 222 → **314px** | 5 → **7줄** |
| 740×360 | 192 → **284px** | 4 → **6줄** |
| 932×430 | 262 → **354px** | 6 → **9줄** |
| 390×844 (세로) | 382 → 382px | 14 → 14줄 (변화 없음) |

### 3-4. 섯다
- `max-width:none` → 폭 사용률 932×430에서 **79→97%**
- `.tablewrap{height:100%}` → 판 844×390 **478×230 → 567×324**, 932×430 **478×230 → 630×364**
- 내 패를 오른쪽 아래 구석으로(`.mine{right:10px}`) → 팟과 **겹침 해소**.
  카드 크기는 안 줄였다 — '밀어서 쪼기'가 이 게임의 알맹이다. 덤으로 오른손 엄지에 붙었다.
- 베팅 버튼 3개씩 두 줄로 접음 → **37px → 78px**(844) / 72px(740) / 86px(932)
- `.seat{transform:translate(-50%,-28%)}` → 자리 잘림 **32px → 0**
- `showSeatSpeech()`가 말풍선을 상단바 아래로 클램프 → 제목 덮임 해소

## 4. 감사기에 추가한 판정 — `npm run audit:landscape`

`scripts/browser-test/audit-landscape.js` 신설. 12종 × 가로 3뷰포트(844×390 · 740×360 · 932×430),
비교군으로 세로 390×844를 같이 잰다.

| # | 판정 | 기준 | 이게 잡는 사고 |
|---|---|---|---|
| ① | 판 점유율 | `판면적/화면면적`이 세로의 **70% 미만** | 알까기 54%·바카라 20% (돌렸더니 판이 작아짐) |
| ② | 폭 낭비 | 실제 그려지는 가로 범위 < 화면 폭의 **80%** | 카드 6종 57% |
| ③ | 잘림 | `overflow:hidden` 조상 밖으로 6px 넘게 나간 자식 | 딜러 패가 판 밖으로 잘림 |
| ④ | 겹침 | 글자 면적의 12% 이상이 카드·주사위와 교차 | 상태 글이 손패 위에 |
| ⑤ | 탭 타깃 | 가로 40px 미만(참고용, 합계 제외) | 섯다 베팅 37px |
| ⑥ | 조작부 도달 | 주 조작 버튼 inView + `elementFromPoint` 가림 | 시작/베팅이 안 눌림 |

설계상 주의 두 가지를 코드 주석에 남겼다.
- **면적을 그냥 비교하면 안 된다** — 360px 화면은 844px 화면보다 원래 작다. 화면 면적으로 정규화한 뒤 견줘야 한다.
  (안 그러면 12종 중 7종이 항상 경고로 뜬다 — 늘 우는 감사는 없느니만 못하다.)
- **조상이 `elementFromPoint`에 잡히는 건 가림이 아니다**(함정 22) — `h.contains(e)`도 통과로 친다.

## 6. 못 고친 것 (임의로 축소하지 않고 남긴다)

1. **상단바 아이콘 버튼이 가로에서 32~36px** (11종 · 40px 하한 미달).
   40px로 키우면 상단바가 6~8px 높아지는데, 그 6~8px이 바로 이번에 판에 준 공간이다.
   원카드는 740×360에서 상태 글과 손패 사이 여유가 **5px**뿐이라 6px을 뺏기면 겹침이 되살아난다.
   → 지금은 `audit:landscape` ⑤가 매번 보고하게만 해뒀다. 판 안쪽을 더 줄이는 다른 처방이 나오면 그때 같이 올릴 것.
   (참고: `.iconbtn::after{inset:-4px}`로 히트박스는 42px이지만, 함정 21대로 **rect로 검증되지 않는 처방은 처방으로 치지 않는다.**)
2. **요트 `#rollBtn` 230×39 · 좌중우 `#rollBtn` 234×38** — 세로 1~2px 부족.
   좌중우는 640×360이 이미 넘침 0으로 빠듯해 여기서 2px을 더 쓰면 다시 넘친다.
3. **원카드/도둑잡기의 더미·버림패 라벨**이 상대가 방금 행동했을 때(행동 배지가 뜬 순간)
   상대 자리 상자 뒤로 잠깐 가린다. 더미 자체는 안 가리고 1초 안에 사라진다 — 조작에는 영향 없음.
4. **≤400px 높이에서 상대의 뒷면 카드 부채를 접었다**(원카드·도둑잡기·인디언).
   장수가 "🃏 6장"으로 이미 숫자로 나오므로 정보 손실은 없지만, 시각적 밀도는 줄었다.
   이건 못 고친 것이 아니라 **의식적으로 맞바꾼 것**이다 — 정보가 겹치는 것보다 장식을 접는 쪽을 골랐다.
5. **알까기 1024×600에서 문서 넘침 +7px** — 이 뷰포트는 높이 600이라 가로 압축 블록(`max-height:520px`)이
   안 걸린다. 이번 변경과 무관한 **기존 상태**이고, `audit:ux`의 뷰포트 목록(1024×768)에도 없다. 별건으로 남긴다.
6. **윷놀이** — 다른 작업자 담당이라 손대지 않았다.
